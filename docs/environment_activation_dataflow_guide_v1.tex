\chapter{编写目的与使用范围}

本文档用于说明数据处理与模型训练过程所需依赖环境的搭建方法，并给出从原始数据到训练数据集的提取边界。
完成部署后，使用者应能够运行快速信号数据库（Fast Signal Database，FSDB）格式转换程序，生成模型所需的特征与标签，并完成代理特征筛选环境的部署。

为兼顾快速使用与细节查阅，正文部分给出必要的环境初始化方法，以及数据集提取和代理筛选快速启动脚本的总体流程与启动方式。
其他具体的脚本功能、参数定义、输入输出件、使用约束和验收要求等细节在附录中展开。
代理筛选算法的原理与完整执行流程另见《代理筛选算法说明》。

Gemmini 硬件加速器平台的生成、仿真与部署可参考 Chipyard 官方文档，本文档不重复介绍相关硬件工具链。
项目后端环境基于华为 Dophis 平台搭建，相关技术资料已较为完善，本文档不再展开说明。

本文档仅适用于功耗预测任务与电压降风险预测任务中，数据处理与模型训练环境准备阶段，内容包括：
\begin{itemize}
  \item FSDB格式转换所需的动态链接库、编译工具和 Python 环境；
  \item 时间窗口样本构造、MCP/XGBoost 代理筛选所需的 Python 环境；
  \item 电平/翻转特征矩阵、功耗标签及电压降风险标签的数据提取与构造流程。
\end{itemize}
本文不涉及 Gemmini 硬件加速器平台部署、Chipyard 工具链安装及华为 Dophis 平台初始化，也不展开模型训练、超参数优化和后端物理设计等流程。
受数据集构建进度限制，电压降风险标签转换目前仍处于接口与算法设计阶段，尚未形成经过完整验证的处理流程。

\chapter{环境部署}

本章说明首次运行前必须具备的两套环境。路径示例均需替换为目标机器上的实际绝对路径，
批处理脚本建议显式传入 \code{PYTHON}，避免登录环境与计算节点解释器不一致。

\section{FSDB格式转换环境部署}

FSDB 格式转换同时依赖 FsdbReader 动态链接库、C++ 编译环境和 Python 数据处理环境。

\subsection{动态链接库与编译环境}

目标机器应提供支持 C++17 的 \code{g++}、\code{make}，
以及可用的 Verdi 2018.09sp2/FsdbReader 安装和配套许可证环境。设置软件包根目录并编译：

\begin{lstlisting}
export PACKAGE_ROOT=/path/to/xgboost_timewindow
cd "${PACKAGE_ROOT}/src/fsdbapi"

# 使用工程内置 FsdbReader 配置
make

# 或显式指定站点 Verdi
make VERDI_HOME=/path/to/verdi/2018.09sp2
\end{lstlisting}

编译后确认两个转换程序存在，且不存在未解析的动态库：

\begin{lstlisting}
test -x build/fsdb_to_tog_cache
test -x build/fsdb_to_power_label
ldd build/fsdb_to_tog_cache | grep 'not found'
\end{lstlisting}

最后一条命令应无输出。还应选取一个实际 FSDB 文件执行最小读取测试，以同时验证动态库版本、FSDB 文件格式和许可证环境。

\subsection{Python环境}

格式转换后的缓存合并、数组转换和特征清洗至少需要 \code{numpy}、\code{scipy} 与 \code{pandas}库，
项目交付文件中附带已经验证的 Conda 环境压缩包 \code{pro.tar.gz}。
环境初始化时，将该文件解压到指定目录并修正环境前缀即可使用，无需重新安装 Python 及相关依赖。

\begin{lstlisting}
# 将交付文件 pro.tar.gz 解压到指定位置
mkdir -p /path/to/conda/envs/pro
tar -xzf /path/to/delivery/pro.tar.gz -C /path/to/conda/envs/pro

# 激活环境并修正打包前缀
source /path/to/conda/envs/pro/bin/activate
conda-unpack

export CONDA_ENV_ROOT=/path/to/conda/envs/pro
export PYTHON=${CONDA_ENV_ROOT}/bin/python
"${PYTHON}" --version
\end{lstlisting}

后续批处理任务可不激活交互式 Conda 环境，但必须显式设置 \code{PYTHON}，确保计算节点使用上述交付环境中的解释器。

\section{代理筛选环境部署}

交付文件中的 \code{pro.tar.gz} 已包含代理筛选与验证所需
的 \code{numpy}、\code{scipy}、\code{pandas}、\code{scikit-learn}、\code{xgboost}、
\code{optuna}、\code{matplotlib}、\code{joblib} 和 \code{skglm} 等依赖，无需另行安装。
按照 2.1.2 节完成解压和前缀修正后，激活 \code{pro} 环境并执行以下命令检查环境完整性：

\begin{lstlisting}
source /path/to/conda/envs/pro/bin/activate
python -m pip check

python - <<'PY'
import sys
import numpy, scipy, pandas, sklearn, xgboost, optuna
import matplotlib, joblib, skglm
print("python", sys.executable)
print("xgboost", xgboost.__version__)
print("skglm", getattr(skglm, "__version__", "unknown"))
print("proxy selection environment: OK")
PY
\end{lstlisting}

\code{python~-m~pip~check}执行完应输出 \code{“No broken requirements found.”}，Python 导入检查应正常结束并打印 
\code{“proxy selection environment: OK”}。
若检查失败，应首先确认当前解释器来自已解压的 \code{pro} 环境，并检查是否已执行 \code{conda-unpack}。

\chapter{代理筛选流程快速启动}

\section{数据集提取快速启动}

\code{cmd/run_fsdb_pipeline.csh} 是当前数据集提取阶段的总控入口。该脚本已实现并验证功耗预测任务的数据处理流程：从 RTL FSDB 导出信号电平/翻转信息，从 PTPX 功耗 FSDB 导出功耗标签，随后完成跨用例合并和无效信息剔除。电压降风险预测任务可复用其中的特征导出、缓存合并和无效信息剔除流程，但受项目阶段与数据采集时间限制，电压降报告及标签尚未完整收集，当前尚未形成经过完整验证的端到端流程。因此，本节将现有脚本作为电压降风险预测数据流的可迁移基线，而不将其表述为已经闭环的电压降数据流。

数据集处理采用分阶段组织方式，各阶段通过文件和 manifest 传递结果，特征提取与标签生成相互解耦。迁移到电压降风险预测标签任务时，无需重写 FSDB 特征处理链，只需替换任务相关的标签生成阶段，并保持用例标识、采样行数和时间对齐关系一致。

\textbf{启动命令示例：}

\begin{lstlisting}
cd /path/to/xgboost_timewindow
csh cmd/run_fsdb_pipeline.csh gemmini
\end{lstlisting}

示例中的 \code{gemmini} 传入脚本后会赋值给环境变量\code{HW}，该变量作为一个区分不同硬件的数据集标签，用于后续输出目录、输出文件的路径生成 。脚本依次完成信号过滤、FSDB 特征分块导出、功耗标签导出、
跨用例缓存合并和无效信息剔除。首次运行前应重点检查下表中的配置。

\begin{longtable}{L{0.20\textwidth}L{0.25\textwidth}L{0.45\textwidth}}

完成后至少检查合并特征 manifest、\code{level} 输出目录与 \code{tog}输出目录中的稀疏矩阵、\code{after_one.namefile.txt}、
标签文件、日志和各级 \code{complete/failed} 标志。当前功耗流程要求同一用例的 Level、Toggle 与功耗标签行数一致。
迁移到电压降风险任务后，还须检查风险矩阵的样本轴与特征行严格对齐。

\section{代理筛选快速启动}

\code{cmd/run_timewindow_pipeline.csh} 以数据集提取结果为输入，代理筛选流程由两个步骤组成：步骤1 构造时间窗口样本，
步骤2 分别对各时间偏移和特征类型执行 MCP 或 XGBoost 代理筛选。使用筛选后的代理训练独立 XGBoost 回归模型进行有效性验证，
以判断代理集合是否保留了足够的功耗预测信息。

\textbf{总控脚本启动示例：}

\begin{lstlisting}
cd /path/to/xgboost_timewindow

# 启用步骤2 代理有效性验证, 并执行数据准备流程
setenv RUN_STEP2_VALIDATION 1
setenv STEP2_VALIDATION_COMBOS "tog_offset12,level_offset12"
csh cmd/run_timewindow_pipeline.csh gemmini
\end{lstlisting}

示例命令中gemmini是硬件标识参数，运行前应检查以下配置。

\midrule
步骤1 & \code{step1_make_global_sample_index.py}、\code{step1_prepare_timewindow.py} & 划分训练/测试样本，并按偏移量和数据类型构造时间窗口特征。 \tabularnewline
步骤2 & \code{step2_mcp_per_offset.py} 或 \code{step2_xgb_per_offset.py}；\code{step2_validation/xgb_power.py} & 对每个时间偏移与特征类型组合执行代理筛选，输出代理列及 manifest；随后重建代理特征并验证功耗预测误差和跳变跟踪能力。 \tabularnewline
\bottomrule
\end{longtable}

运行脚本后，流程会自动调用 \code{step1_make_global_sample_index.py} 和 \code{step1_prepare_timewindow.py} 
完成训练/测试样本划分及时间窗口特征构造。
随后根据 \code{PROXY_SELECTOR} 调用 \code{step2_mcp_per_offset.py} 或 \code{step2_xgb_per_offset.py}，
对各时间偏移与特征类型组合分别执行代理筛选。
启用验证功能时，还会调用 \code{step2_validation/xgb_power.py}，读取时间窗口清单和代理清单，重建该组合对应的代理特征，
并训练独立的 XGBoost 回归模型进行初步验证。


代理筛选结果保存在 \code{step2_mcp/mcp_per_offset_manifest.json} 或 
\code{step2_xgb_proxy/mcp_per_offset_manifest.json} 中，各组合的代理索引由其中的 \code{selected_indices_file} 给出。
验证程序按 \code{<hpotag>/<target>-bc<before_cycles>/} 动态生成结果目录，并在其 \code{eval/} 子目录输出初步评价。
其中 \code{point_metrics.csv} 给出平均绝对百分比误差（Mean Absolute Percentage Error，MAPE）、
决定系数（Coefficient of Determination，$R^2$）和归一化均方根误差（Normalized Root Mean Squared Error，NRMSE）等预测指标。

迁移至电压降风险预测任务时，步骤1 需将 \code{LABEL_DIR} 指向与特征对齐的0/1风险标签，
并将连续功耗标签读取逻辑改为风险矩阵读取逻辑；现有 \code{xgb_power.py} 使用连续值功耗标签和回归目标，
不能直接作为电压降风险验证程序，必须将标签接口、XGBoost 目标函数和评价指标替换为二分类或多输出风险预测实现。
由于风险标签及空间映射尚未完成验证，上述内容仅说明流程的可迁移边界，不代表当前完整可执行的电压降代理筛选流程。
